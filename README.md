# Мониторинг аренды → Telegram

Раз в 10 минут проверяет новые объявления об аренде квартир на трёх сайтах,
отсеивает неподходящие и присылает остальное в Telegram с фото и кнопкой
на объявление.

Ничего, кроме GitHub, поднимать не нужно: расписание — GitHub Actions,
состояние — файл `state.json` в этом же репозитории.

## Источники

| Сайт | Как берём данные | Сортировка по свежести |
|---|---|---|
| **4zida.rs** | список из `ld+json` на странице поиска, детали — из открытого JSON API `api.4zida.rs/v6/ads/<id>` | `?sortiranje=najnoviji` |
| **nekretnine.rs** | всё лежит в `__NEXT_DATA__` на странице поиска, отдельный запрос не нужен | `?criterio=data&ordine=desc` |
| **oglasi.rs** | микроразметка schema.org плюс подписанные поля в HTML | `?s=d` |

Общее для всех: сортируем по свежести, берём первые 1–2 страницы, сверяем ID
с тем, что уже показывали. Полная карточка запрашивается только для новых
объявлений (и только на 4zida — остальные отдают всё сразу), поэтому обычный
проход стоит 5–6 запросов на все три сайта.

### halooglasi.com — не подключён

Весь домен закрыт Cloudflare-челленджем: любой запрос без браузера получает
403 «Just a moment...», включая `sitemap.xml`, который они сами указывают
в `robots.txt`. Чтобы его обойти, нужен headless-браузер, который будет решать
антибот-проверку — это уже обход защиты, а не чтение открытых данных, и такой
код ломался бы после каждого обновления Cloudflare. Их `robots.txt` вдобавок
отдельно запрещает краулеры ИИ-сервисов и ставит `ai-train=no`.

Если сайт нужен — практичнее подписаться на их собственные email-уведомления
о новых объявлениях и настроить пересылку в Telegram.

### Почему это законно и вежливо

- **robots.txt.** На 4zida открыт весь поиск (закрыты избранное, печать,
  `/agenti/`), там же лежит `llms.txt` с прямым приглашением забирать актуальные
  страницы. На nekretnine.rs запрещён внутренний API `/search-list` — поэтому мы
  его и не трогаем, а читаем обычную страницу поиска. На oglasi.rs запрещены
  `/oglasi?q=` и `/oglasi?o=` — наши адреса не из этого раздела.
- **Частота.** Один запрос в секунду, 5–6 запросов раз в 10 минут. Это меньше,
  чем человек, обновляющий вкладку.
- **User-Agent.** Браузерный (иначе nekretnine.rs отвечает 403), но с припиской
  `rent-watcher/1.0`, чтобы в логах сайта было видно, кто ходит и зачем.

## Три особенности, на которые ушло больше всего времени

**ID объявления на 4zida — это MongoDB ObjectId.** В первых 4 байтах лежит
unix-время создания, поэтому точный возраст объявления считается из самого ID,
без единого запроса.

**nekretnine.rs отвечает `103 Early Hints`.** Модуль `http.client` в Python
возвращает этот промежуточный ответ вместо финального `200`, и тело приходит
пустым — на этом молча ломаются и `requests`, и `urllib`. Поэтому в проекте
`httpx`: он разбирает такие ответы правильно.

**nekretnine.rs блокирует по своей же cookie.** Сайт использует DataDome: первым
ответом ставит куку `datadome`, и если вернуть её следующим запросом — 403.
Поэтому куки между запросами не сохраняются. Ровно так по умолчанию ведёт себя
`curl`, из-за чего он работал там, где падал клиент с общим cookie-jar.

## Где хранится состояние

В `state.json` — список ID уже показанных объявлений (с префиксом источника,
чтобы ID разных сайтов не пересекались) и отметка, какие поиски уже проходили
первый запуск. Файл коммитится обратно в репозиторий, но **только когда нашлось
что-то новое**: пустые проходы не создают коммитов. Побочный эффект приятный —
`git log` показывает, когда и сколько квартир появлялось.

Помним последние 5000 ID (около 165 КБ).

## Установка

### 1. Telegram-бот

1. Открой в Telegram [@BotFather](https://t.me/BotFather), отправь `/newbot`.
2. Придумай имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AAH...` — это `TELEGRAM_BOT_TOKEN`.
4. Напиши своему новому боту любое сообщение (иначе он не сможет тебе ответить).
5. Узнай свой `chat_id` — открой в браузере, подставив токен:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   В ответе найди `"chat":{"id":123456789` — это `TELEGRAM_CHAT_ID`.

Чтобы уведомления шли вам обоим, создай группу, добавь туда бота и возьми
`chat_id` группы из того же `getUpdates` (у групп он отрицательный).

Важная деталь про группы: у ботов по умолчанию включён Privacy Mode, поэтому
обычных сообщений в группе бот не видит и `getUpdates` вернёт пустой список.
Отправку это не ограничивает — режим стоит оставить включённым. Чтобы всё-таки
получить `chat_id`, напиши в группе команду, адресованную боту: `/start@ИмяБота`.
Такие сообщения он получает и в Privacy Mode.

### Отдельная тема вместо General

Если группа переведена в режим форума (с темами), по умолчанию сообщения
уходят в General. Чтобы писать в конкретную тему, задай `TELEGRAM_TOPIC_ID`.
Узнать его можно двумя способами:

- отправить `/start@ИмяБота` **внутри нужной темы** и найти в `getUpdates`
  поле `message_thread_id`;
- скопировать ссылку на тему (долгое нажатие по ней в списке тем → Copy Link):
  в `https://t.me/c/<группа>/<тема>` последнее число и есть ID.

Переменная необязательная: пустая или отсутствующая — сообщения идут в General.

### 2. Локальная проверка

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполни значения
set -a && source .env && set +a
.venv/bin/python watch.py --dry-run
```

`--dry-run` показывает, что было бы отправлено, не записывая `state.json`
и не отправляя сообщений.

### 3. GitHub Actions

Залей репозиторий на GitHub, затем Settings → Secrets and variables → Actions →
New repository secret, и добавь секреты: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
и, если нужна отдельная тема, `TELEGRAM_TOPIC_ID`.

Дальше [`.github/workflows/watch.yml`](.github/workflows/watch.yml) запускается сам.
Первый запуск можно сделать руками: вкладка Actions → 4zida watcher → Run workflow.

**Важно про первый проход.** Каждый поиск при первом запуске молча запоминает
текущую выдачу и не шлёт ни одного сообщения — иначе прилетело бы полсотни
уведомлений о квартирах, которые висят на сайтах неделю. Уведомления начнутся
со второго прохода.

## Настройка фильтров

Всё в [`config.yaml`](config.yaml). Блок `filters` наверху действует на все
поиски; любой поиск может переопределить отдельные поля своим блоком `filters`.

| Поле | Что делает |
|---|---|
| `price_min` / `price_max` | цена в EUR за месяц |
| `m2_min` / `m2_max` | площадь |
| `rooms_min` / `rooms_max` | комнаты; `1.5` = jednoiposoban, `2.0` = dvosoban |
| `furnished` | `yes` / `no` / `null`; **есть только у 4zida и oglasi** |
| `only_private` | `true` — скрыть агентства |
| `exclude_keywords` | отсев по словам в описании и заголовке |

Про `only_private` стоит знать две вещи. На oglasi.rs продавец в выдаче не
показан вообще — такие объявления фильтр пропускает (лучше лишнее сообщение,
чем потерянная квартира), и в сообщении строка про продавца просто не выводится.
А на nekretnine.rs объявлений от частников практически нет — включив этот фильтр,
вы отключите сайт целиком.

`url` в каждом поиске — адрес со страницы сайта. Накликай фильтры в их
интерфейсе и скопируй адрес из строки браузера: так работают любые фильтры
сайта, включая те, которых нет в конфиге. Сортировку дописывать не нужно.

## Эксплуатация

- **Интервал.** Меньше 5 минут GitHub Actions не даёт, и запуск может
  задержаться на несколько минут под нагрузкой. Для аренды это приемлемо.
- **Падение одного сайта не ломает остальные** — ошибка логируется, проход
  продолжается. Если сайт поменяет вёрстку, это будет видно в логах Actions
  как `ОШИБКА в поиске «...»`.
- **Пропущенные объявления.** Если сайт выложит пачку разом — подними
  `max_pages` до 3.

## Как добавить ещё один сайт

Новый модуль в [`sources/`](sources/) с двумя вещами: `NAME` и функция
`fetch(url, page)`, возвращающая объявления в общем формате (он описан
в [`sources/__init__.py`](sources/__init__.py)). Если детали приходится
догружать отдельным запросом — добавь `enrich(item)`, она вызывается только
для новых объявлений. Дальше — вписать модуль в `SOURCES` и добавить блок
в `config.yaml`.
